# Security Policy

## Project status

DocsShield is in early development and is not yet suitable for production or for making high-stakes decisions about document safety.

## Reporting a vulnerability

Please do not disclose exploitable vulnerabilities, private documents, or personal data in public issues.

Use GitHub's private vulnerability reporting feature if it is enabled for this repository. Otherwise, contact the repository maintainer privately through the contact options on the GitHub profile.

Include:
- A concise description of the issue.
- Reproduction steps using non-sensitive test files.
- The affected commit, version, or component.
- Potential impact and any suggested mitigation.

## Scope

Security reports involving unsafe document parsing, archive/XML handling, parser crashes, resource exhaustion, path traversal, unsafe temporary-file handling, data leakage, and bypasses in detection logic are especially relevant.

## Safe testing

Only test systems and documents you own or are explicitly authorized to assess. Do not submit confidential or personal documents as proof of concept.
